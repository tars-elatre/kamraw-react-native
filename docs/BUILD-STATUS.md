## Sign-in replacement

Auth0 SDKs, native plugin and configuration requirements are removed from the mobile app, API and dashboard. Phone sign-in uses a five-minute, single-use demo code and creates a customer account; sample customer/creator/staff workspaces remain available in demo mode. Opaque session tokens are hashed in the database, expire, and revoke on logout. Mobile credentials use native SecureStore or tab-scoped browser storage. A temporary network failure preserves the cached account; a rejected session returns to sign-in. Tests cover expiry, replay, concurrent verification, five-attempt lockout, resend invalidation, role isolation, logout and mobile restoration. Local browser verification confirmed phone sign-in and session restoration after reload. No SMS is sent in demo mode. Live SMS delivery and staff MFA are still launch dependencies, with live demo access disabled.

Booking validation now names the missing venue/contact detail and stops progression before an invalid session can be copied or quoted. Browser QA also verified creator login, profile/performance access, logout and operations login with Kamraw-managed sessions.
